## 1. 快速概览

这个模块封装了视觉端与下位机（STM32）之间的串口通信，提供：

| 能力 | 说明 |
|------|------|
| **打开串口** | 从 YAML 加载配置，用 `wjwwood/serial` 库打开端口 |
| **接收数据** | 读取字节流 → 粘包/拆包 → 解析出四元数/模式/裁判数据 |
| **发送数据** | 填充 `SendPacket`（瞄准角度/速度）→ 写入串口 |
| **四元数插值** | 用滑动窗口 + slerp 平滑插值出任意时刻的姿态 |
| **断线重连** | 检测异常 → 5 秒节流重连，清空旧数据 |

## 2. 架构总览

串口通信分成**三层**，各管一件事：

```
┌─────────────────────────────────────────────────────┐
│ ① 协议层 (serial_types.hpp)                          │
│    定义收发包的字节格式：0xAA/0xBB 帧头、字段顺序     │
│    ── "线路上这些字节代表什么意思"                    │
├─────────────────────────────────────────────────────┤
│ ② 驱动层 (user_serial.cpp / user_serial.hpp)         │
│    收发字节、粘包拆包、解析协议、四元数插值、重连     │
│    ── "怎么把字节搬来搬去、怎么解析"                  │
├─────────────────────────────────────────────────────┤
│ ③ 线程层 (serial_thread.cpp)                         │
│    固定频率循环：定时发、持续收                        │
│    ── "什么时候收发"                                  │
└─────────────────────────────────────────────────────┘
```

**核心数据流（接收方向）：**

```
STM32 ──串口字节流──▶ receiveSerial()
                       │  available()/read() 读字节
                       ▼
                    recv_buffer_ (累积缓冲区)
                       │  找 0xAA 帧头 + 验 0x5A 帧尾
                       ▼
                    ReceivePacket (memcpy 解析)
                       │  拆出四元数 / 模式 / 裁判数据
                       ├──▶ data_queue_ (SPSCQueue) ──▶ q(t) 插值 ──▶ 上层
                       ├──▶ vision_mode_ (原子/普通成员)
                       └──▶ referee_data_ (裁判系统数据)
```

**发送方向：**

```
上层 ──sendVision/sendNav──▶ send_packet_ (填充) ──sendPacketToSerial()──▶ write() ──▶ STM32
```

## 3. serial_types.hpp — 协议层

这是理解一切的前提：串口线路上传的**到底是一串什么字节**。三个关键点先记住：

1. **`__attribute__((packed))`**：让结构体成员紧密排列、不加填充字节，保证"内存布局 = 线路上传输的字节顺序"，`memcpy` 收发才不会错位。
2. **帧头 + 帧尾**：用固定字节（0xAA/0x5A）标记一帧的起止，用于在连续的字节流里"切出完整的一帧"。
3. **`#define SENTRY`**（第 8 行）：定义了哨兵模式宏，使 `ReceivePacket` 里带上裁判系统数据。

### 3.1 RefereePacket — 裁判系统数据

```cpp
struct __attribute__((packed)) RefereePacket {
    uint16_t projectile_allowance_17mm;       // 剩余发弹量 (2字节)
    uint8_t  power_management_shooter_output; // 功率管理 shooter 输出 (1字节)
    uint16_t current_hp;                      // 机器人当前血量 (2字节)
    uint16_t outpost_HP;                      // 前哨站血量 (2字节)
    uint16_t base_HP;                         // 基地血量 (2字节)
    uint8_t  game_progess;                    // 比赛进程 (1字节)
};
```

> **字段来源**：这些字段来自 RoboMaster 官方裁判系统协议，但这是你们自己封装的简化结构体。总大小 = 2+1+2+2+2+1 = **10 字节**（packed 后无填充）。

### 3.2 ReceivePacket — 接收帧（下位机 → 视觉）

```cpp
#ifdef SENTRY
struct __attribute__((packed)) ReceivePacket {
    uint8_t header = 0xAA;     // 帧头 (1字节)
    uint8_t mode;              // 视觉模式 (1字节)
    float   q[4];              // 四元数 wxyz (16字节)
    RefereePacket referee_data; // 裁判数据 (10字节)
    uint8_t tail = 0X5A;       // 帧尾 (1字节)
};
#else
// 无 referee_data，其余相同
#endif
```

| 字段 | 类型 | 含义 |
|------|------|------|
| `header` | `uint8_t` | 帧头固定 `0xAA`，用于定位一帧的起点 |
| `mode` | `uint8_t` | 视觉模式，映射到 `VisionMode` 枚举（见 3.4） |
| `q[4]` | `float[4]` | 四元数，`wxyz` 顺序，表示机器人当前姿态朝向 |
| `referee_data` | `RefereePacket` | 裁判系统数据（仅 `SENTRY` 宏定义时存在） |
| `tail` | `uint8_t` | 帧尾固定 `0x5A`，用于校验这一帧是否完整 |

> **SENTRY 模式下总大小** = 1+1+16+10+1 = **29 字节**。非 SENTRY 模式 = 1+1+16+1 = **19 字节**。这个大小就是后面 `receiveSerial()` 里 `sizeof(ReceivePacket)` 的依据。

### 3.3 SendPacket — 发送帧（视觉 → 下位机）

```cpp
struct __attribute__((packed)) SendPacket {
    uint8_t header = 0XBB;    // 帧头 (1字节)
    uint8_t found;            // 是否找到目标 (1字节)
    uint8_t fire_advice;      // 开火建议 (1字节)
    float   target_yaw;       // 目标 yaw 角度 (4字节)
    float   target_pitch;     // 目标 pitch 角度 (4字节)
    float   vx;               // x 方向速度 (4字节)
    float   vy;               // y 方向速度 (4字节)
    uint8_t nav_state;        // 导航状态 (1字节)
    uint8_t tail = 0X5B;      // 帧尾 (1字节)
};
```

> **总大小** = 1+1+1+4+4+4+4+1+1 = **21 字节**。发送端用 `0xBB`/`0x5B` 与接收帧 `0xAA`/`0x5A` 区分方向。

### 3.4 VisionMode — 视觉模式枚举

```cpp
enum VisionMode {
    AUTO_AIM_RED    = 0,   // 自瞄红方
    AUTO_AIM_BLUE   = 1,   // 自瞄蓝方
    SMALL_RUNE_RED  = 2,   // 小能量机关红方
    SMALL_RUNE_BLUE = 3,   // 小能量机关蓝方
    BIG_RUNE_RED    = 4,   // 大能量机关红方
    BIG_RUNE_BLUE   = 5,   // 大能量机关蓝方
};
```

`ReceivePacket.mode` 字段（0~5）对应这个枚举，下位机通过它告诉视觉"现在打什么模式"。

### 3.5 辅助结构体

| 结构体 | 用途 |
|--------|------|
| `ReceivedDataMsg` | 接收数据的消息（四元数 + 模式 + 时间戳），供队列/上层使用 |
| `QuaternionWithTimestamp` | 带时间戳的四元数，实际存进 `data_queue_` 的类型 |

## 4. serial_config.yaml — 配置层

```yaml
serial:
  debug: false          # 是否打印接收到的原始字节(HEX)
  port: "/dev/mascdc"   # 串口设备文件（udev 固定的名字）
  baudrate: 115200      # 波特率
  timeout: 2            # 读写超时(毫秒)
  bytesize: 8           # 数据位
  parity: "none"        # 校验位
  stopbits: 1           # 停止位
  flowcontrol: "none"   # 流控
```

> **为什么端口是 `/dev/mascdc`？** 这是 `setup_serial_device.sh` 用 udev 规则为 USB 转串口芯片（CH340/CP2102 等）创建的**固定别名**。因为 `/dev/ttyUSB0` 这种名字插拔后会变，固定成 `/dev/mascdc` 才能在配置里写死。

> **⚠️ 关键：这些参数必须和 STM32 端完全一致。** 波特率、数据位、校验位、停止位差一个，收到的就是乱码。

## 5. user_serial.hpp — 蓝图

头文件是理解整个类的**地图**。

### 5.1 单例模式

```cpp
UserSerial(const UserSerial&)            = delete;
UserSerial& operator=(const UserSerial&) = delete;

static UserSerial& getInstance(const std::string& config_path = "config/serial_config.yaml") {
    static UserSerial instance(config_path);  // 函数内静态变量，线程安全
    return instance;
}
```

- 禁止拷贝/赋值，保证全局只有一个串口对象。
- `getInstance()` 用**函数内静态变量**实现单例，C++11 起保证线程安全，且首次调用才构造（懒加载）。

### 5.2 成员变量一览

| 成员 | 类型 | 含义 |
|------|------|------|
| `serial_port` | `shared_ptr<serial::Serial>` | 串口对象（第三方库 wjwwood/serial），所有读写都靠它 |
| `isConnected` | `atomic<bool>` | 连接状态 |
| `send_packet_` | `SendPacket` | 发送数据包（复用同一个，每次填充字段） |
| `recv_buffer_` | `vector<uint8_t>` | 接收累积缓冲区（处理粘包/半包） |
| `temp_read_buf_` | `vector<uint8_t>` | 单次读取的临时缓冲区（256 字节） |
| `data_queue_` | `SPSCQueue<QuaternionWithTimestamp>` | 四元数队列，容量 5000，无锁 |
| `data_ahead_` / `data_behind_` | `QuaternionWithTimestamp` | 插值滑动窗口的前后两个采样点 |
| `vision_mode_` | `VisionMode` | 当前视觉模式 |
| `referee_data_` | `RefereePacket` | 最新裁判系统数据 |
| `has_received_data_` | `atomic<bool>` | 是否收到过至少一次有效数据 |

### 5.3 公有接口一览

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `sendVision(yaw, pitch, found, fire)` | `void` | 填充瞄准相关字段（不发，只是改 `send_packet_`） |
| `sendNav(vx, vy, nav_state)` | `void` | 填充导航相关字段 |
| `sendPacketToSerial()` | `void` | 真正把 `send_packet_` 写入串口 |
| `receiveSerial()` | `void` | 读取并解析串口数据 |
| `reconnect()` | `void` | 断线重连 |
| `q(t)` | `Quaterniond` | 插值出指定时刻 t 的四元数 |
| `isQuaternionValid()` | `bool` | 四元数数据是否有效（未超时） |
| `getVisionMode()` | `VisionMode` | 获取当前模式 |
| `getRefereeData()` | `RefereePacket` | 获取裁判数据 |
| `isConnectedStatus()` | `bool` | 连接状态 |

> **`sendVision`/`sendNav` 只是"改数据"，`sendPacketToSerial` 才是"发出去"。** 这个拆分让上层可以多次更新字段，最后由线程统一发送，避免每次改字段都触发一次写串口。

## 6. user_serial.cpp — 核心实现

这个文件是**重点**，按函数逐个拆解。

### 6.1 构造函数 `UserSerial(config_path)`

负责：加载配置 → 打开串口 → 初始化状态。

```
步骤1: 读取 YAML 配置文件（serial 段）
        ├─ debug / port / baudrate / timeout / bytesize / parity / stopbits / flowcontrol
        └─ 把字符串配置转成 serial 库的枚举 (bytesize_t/parity_t/stopbits_t/flowcontrol_t)

步骤2: 初始化缓冲区
        ├─ recv_buffer_.reserve(1024)   // 接收累积区预留 1KB
        └─ temp_read_buf_.resize(256)   // 单次读取 256 字节

步骤3: 初始化状态
        ├─ last_data_receive_time_ = epoch  // 确保收到首个数据包前 isQuaternionValid() 返回 false
        ├─ has_received_data_ = false
        └─ data_ahead_/data_behind_ 初始化为单位四元数 + epoch 时间戳

步骤4: 打开串口
        serial_port = make_unique<serial::Serial>(port_, baudrate_, Timeout::simpleTimeout(timeout_), ...)
        ├─ 打开成功 → isConnected = true
        └─ 打开失败/异常 → isConnected = false，直接 return
```

**配置字符串 → 枚举的映射**（关键转换）：

| 配置值 | 枚举 |
|--------|------|
| `bytesize: 8` | `serial::eightbits` |
| `parity: "none"` | `serial::parity_none` |
| `stopbits: 1` | `serial::stopbits_one` |
| `flowcontrol: "none"` | `serial::flowcontrol_none` |

> **`Timeout::simpleTimeout(timeout_)`** 是 serial 库的便捷函数，生成一个"绝对超时"配置。timeout=2 表示读写超过 2ms 就返回（不会永久阻塞）。

### 6.2 发送：`sendVision` / `sendNav` / `sendPacketToSerial`

```cpp
// 只改字段，不发
void sendVision(yaw, pitch, found, fire_advice) {
    send_packet_.target_yaw   = target_yaw;
    send_packet_.target_pitch = target_pitch;
    send_packet_.found        = found;
    send_packet_.fire_advice  = fire_advice;
}

// 真正发送
void sendPacketToSerial() {
    // ① 未连接则先重连（阻塞直到连上或 g_shutdown）
    while (!g_shutdown && (!isConnected || !serial_port || !serial_port->isOpen())) {
        reconnect();
    }
    if (g_shutdown) return;

    // ② 把整个结构体按字节写出去
    serial_port->write(reinterpret_cast<const uint8_t*>(&send_packet_), sizeof(SendPacket));
}
```

**关键点：**

- `send_packet_` 是**复用同一个对象**，每次 `write` 直接把整个结构体的内存按 21 字节写出去。因为它是 `packed` 结构体，字节排布和下位机约定一致。
- `reinterpret_cast<const uint8_t*>(&send_packet_)`：把结构体指针转成"字节指针"，`write` 才知道要发哪些字节。

> **⚠️ 注意（可留意的细节）**：`send_packet_` 的初始化列表 `{0XBB, 0, 0, 0, 0, 0.0f, 0.0f, 0X5B}` 只有 **8 个值**，而 `SendPacket` 有 **9 个字段**。结果第 8 个值 `0X5B` 被赋给了 `nav_state`（而不是 `tail`），`tail` 则靠成员默认值 `0X5B` 兜底。这意味着 `nav_state` 的初值被设成了 `0x5B`(91)。由于后续 `sendNav()` 会覆盖 `nav_state`，实际影响不大，但严格说初值不太干净，值得留意。

### 6.3 接收：`receiveSerial()` — 粘包/拆包核心

这是**整块最该吃透的函数**。串口是字节流，没有"帧边界"的概念，你必须自己从连续的字节里切出完整的一帧。

```
① 未连接则先重连

② available() 看有多少字节可读
   ├─ 0 字节 → 本轮无事，直接返回
   └─ >0 字节 ↓

③ read(temp_read_buf_, bytes_to_read)
   把读到的字节追加到 recv_buffer_ 末尾

④ 循环解析 recv_buffer_（只要长度 >= sizeof(ReceivePacket)）：
   ├─ 找帧头 0xAA
   │    ├─ 找不到 → 清空 recv_buffer_（全是垃圾），break
   │    └─ 找到，但 0xAA 前面有字节 → 删掉 0xAA 之前的所有字节（丢弃不完整头）
   ├─ 长度不够一帧 → break（等下次多读点）
   ├─ memcpy 成 ReceivePacket
   ├─ 验帧尾 packet.tail == 0x5A？
   │    ├─ 是 → 有效帧 ↓
   │    │      ├─ 更新 last_data_receive_time_（心跳）
   │    │      ├─ has_received_data_ = true
   │    │      ├─ 四元数 q[4] → Eigen::Quaterniond，normalize()
   │    │      ├─ push 进 data_queue_
   │    │      ├─ SENTRY 模式：更新 referee_data_
   │    │      ├─ 从 recv_buffer_ 删除这一整帧
   │    │      └─ 按 mode 更新 vision_mode_
   │    └─ 否 → 删掉最前面 1 个字节，继续找下一个 0xAA
```

#### 为什么要"粘包/拆包"

串口一次 `read` 读到的字节，**不一定刚好是一帧**：

- **粘包**：一次读到两帧甚至更多帧的数据（`recv_buffer_` 里有多帧）。
- **半包/拆包**：一次只读到半帧（帧头来了，帧尾还没到）。

所以 `receiveSerial()` 用 `recv_buffer_` 做**累积**，然后用"找帧头 + 验帧尾"的逻辑，把字节流**重新切成一帧一帧**。

#### 帧头/帧尾校验的健壮性

- 找 `0xAA`：用 `std::find` 定位，删掉前面的垃圾字节——这样即使之前有乱数据，也能重新对齐。
- 验 `0x5A`：`0xAA` 可能出现在数据中间（比如四元数的某个字节恰好是 0xAA），所以还要靠帧尾 `0x5A` 二次确认。帧尾不对就**只删 1 字节**再重试，而不是直接清空——避免误删后面正确的帧。

#### debug 模式

`debug_ = true` 时，会把收到的每个字节打印成 HEX（`snprintf(buf, "%02X ")`），方便用串口助手对照排查。

### 6.4 重连：`reconnect()`

```
① g_shutdown → 直接 return

② 节流：距上次重连 < 5000ms → sleep(100ms) 后 return
   （防止疯狂重连打爆 CPU）

③ 更新 last_reconnect_time_

④ 关闭旧串口 + reset 指针 + isConnected = false

⑤ 清空 data_queue_（旧数据不要了）

⑥ has_received_data_ = false（但不重置时间戳）

⑦ 重新 make_shared<serial::Serial>(...) 打开
   ├─ 成功 → isConnected = true
   └─ 失败 → isConnected = false（下次再试）
```

| 关键设计 | 原因 |
|----------|------|
| 5 秒节流 | 串口断线后疯狂重试会占满 CPU，5 秒一次足够 |
| 重连前清空 `data_queue_` | 旧的四元数数据已过时，插值会用到错误姿态 |
| 重置 `has_received_data_` 但不重置时间戳 | 保证重连后 `isQuaternionValid()` 先返回 false，直到收到新数据 |

### 6.5 `isQuaternionValid()` — 数据有效性检查

```cpp
bool isQuaternionValid() const {
    if (!has_received_data_.load())  return false;   // 从未收到过数据
    if (data_age_ms > DATA_TIMEOUT_MS) return false; // 数据超时(>1秒)
    if (data_queue_.empty())          return false;  // 队列空
    return true;
}
```

三重检查：**收到过数据 + 没超时（1 秒内）+ 队列非空**。上层调用前先判断，避免用过期/无效的姿态。

### 6.6 `q(t)` — 四元数时间插值（滑动窗口 + slerp）

这是最"有技术含量"的一段。下位机以固定频率发四元数，但上层想要**某个任意时刻 t** 的姿态，而 t 往往夹在两个采样点之间。于是用**滑动窗口** + **球面线性插值(slerp)** 算中间值。

#### 滑动窗口：`data_ahead_`（前点）+ `data_behind_`（后点）

```
时间轴 →     t_a            t_b
            data_ahead_    data_behind_
              (旧采样)       (新采样)
                    ↑
                    目标时刻 t 夹在中间
```

#### 算法步骤

```
① 搬运队列 → 更新窗口
   while (data_behind_.timestamp < t) {   // 后点还比 t 旧，窗口要往前滚
       data_ahead_  = data_behind_;       // 旧的后点变成新的前点
       ptr = data_queue_.front();         // 从队列取更新的数据
       if (ptr == nullptr) break;         // 队列空了，没新数据，只能外推
       data_behind_ = *ptr; data_queue_.pop();
   }

② 边界：窗口未初始化（data_ahead_ 还是 epoch）→ 直接返回 data_behind_.quaternion

③ 计算插值系数 k
   k = (t - t_a) / (t_b - t_a)
   k = clamp(k, 0, 1)   // 限制在 [0,1]，不做外推（防抖动）

④ 四元数符号一致性
   if (q_a.dot(q_b) < 0) q_b = -q_b;   // 确保走"最短路径"插值

⑤ slerp 插值 + 归一化
   return q_a.slerp(k, q_b).normalized();
```

| 关键点 | 为什么 |
|--------|--------|
| `k` 限制在 `[0,1]` | 只做"内插"不做"外推"，防止 t 超出窗口时姿态跳变 |
| 符号一致性检查 `dot < 0` | 四元数 q 和 -q 表示同一个旋转，但插值时若符号相反会走"绕远路"，翻转后走最短路径 |
| `normalize()` | 插值结果可能不再是单位四元数，归一化保证旋转有效 |
| 队列空了就 break | 没新数据时不强行外推，退回用当前 `data_behind_` 返回 |

> **slerp（球面线性插值）**：在四维球面上做插值，比直接线性插值四元数分量更平滑、更符合旋转的物理意义。Eigen 的 `Quaterniond::slerp()` 已经帮你实现好了。

## 7. serial_thread.cpp — 串口线程

这是串口模块的**入口**，把上面的收发函数放进一个循环里跑。

```cpp
void serial_thread_func() {
    UserSerial &serial = UserSerial::getInstance();  // 拿到单例

    auto last_send_time = steady_clock::now();
    const auto send_interval = 4ms;                  // 发送间隔 = 4ms = 250Hz

    while (!g_shutdown) {
        // 发送：每 4ms 发一次（固定 250Hz）
        if (now - last_send_time >= send_interval) {
            serial.sendPacketToSerial();
            last_send_time = now;
        }
        // 接收：每轮都收
        serial.receiveSerial();
        sleep(1ms);
    }
    serial.closeSerial();
}
```

**节奏设计：**

| 操作 | 频率 | 说明 |
|------|------|------|
| 发送 | **250Hz**（每 4ms） | 视觉角度要高频下发给下位机做云台控制 |
| 接收 | 每轮都收 | 下位机数据来了就收，不主动限频 |
| 循环体 | sleep 1ms | 避免忙等空转 |

> **为什么发送用固定 250Hz？** 云台控制需要稳定的控制频率，发送太快浪费、太慢云台响应不及时。4ms 一个周期是视觉→下位机的典型刷新率。

## 9. 关键设计决策总结

| 设计 | 为什么？ |
|------|---------|
| `__attribute__((packed))` 结构体 | 内存布局 = 线路上字节顺序，`memcpy` 收发不错位 |
| 帧头 `0xAA`/`0xBB` + 帧尾 `0x5A`/`0x5B` | 字节流无边界，靠头尾标记切帧 |
| 接收用 `recv_buffer_` 累积 | 解决粘包/半包问题 |
| `sendVision` 只改数据、`sendPacketToSerial` 才发 | 解耦"改字段"和"发数据"，允许高频填充 + 定时发送 |
| 单例模式 | 全局唯一串口，避免两个对象同时抢同一个端口 |
| `data_queue_` SPSCQueue 容量 5000 | 无锁队列，接收线程和插值消费者解耦 |
| 滑动窗口 + slerp 插值 | 拿到任意时刻平滑姿态，避免采样点之间跳变 |
| 5 秒重连节流 | 防疯狂重试占满 CPU |
| 1 秒数据超时 (`DATA_TIMEOUT_MS`) | 太久的数据不可信，视为无效 |
